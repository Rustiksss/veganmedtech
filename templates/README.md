# Шаблоны SDD

Сначала подготовьте рабочую задачу в [CURRENT_TASK.md](../CURRENT_TASK.md) по [шаблону](current-task.md): подробно опишите результат, способ выполнения и критерии самопроверки. Передайте конкретную редакцию разработчику на ревью и дождитесь аппрува. До него изменения других файлов не выполняются. Незавершённую текущую задачу нельзя перезаписывать новой.

Принцип минимализма: реализовывайте только необходимое сейчас. Для каждой функции укажите требование PDF или пункт [брейншторма](../docs/product/brainstorm.md), для технического решения — необходимость в текущей задаче. Не добавляйте функции, зависимости и структуры «на будущее»; необоснованные расширения удаляйте из планов. Проверки доступа, подтверждение врача и самопроверка обязательны.

Создание или изменение комплекта спецификации выполняйте внутри согласованной задачи. Номер функции выбирается следующим свободным в `specs/`; ID требований берутся из [реестра](../docs/product/requirements.json). Эти команды выполняются после аппрува:

```sh
mkdir -p specs/002-your-feature
cp templates/spec.md templates/plan.md templates/tasks.md templates/acceptance.md templates/traceability.json specs/002-your-feature/
```

1. Замените **все** заполнители `{{...}}`, включая имена и ID в JSON. Число `002` и имя каталога в примере — только пример; сверьтесь с бэклогом.
2. Укажите источник функции, её необходимость сейчас, границы и наблюдаемые критерии. Добавьте значимый негативный сценарий по риску задачи.
3. Заполните план, задачи и приёмку. Свяжите каждое требование с критериями и тестами в `traceability.json`; `partial` не закрывает требование целиком.
4. Удалите неподходящие пункты, расширьте набор сценариев по риску. Ни один тест заранее не помечайте пройденным.
5. Выполните `python3 scripts/check_sdd.py`.

Статус спецификации `ready` не заменяет аппрув текущей задачи. Во время выполнения сразу записывайте обнаруженный техдолг в [TECH_DEBT.md](../TECH_DEBT.md). После самопроверки каждого критерия обновите [PROJECT_STATUS.md](../PROJECT_STATUS.md), результат проверки долга и трассировку. Завершённую рабочую задачу перенесите в [архив](../tasks/completed/README.md), восстановите текущий файл в `idle` и повторно проверьте ссылки.

Для архитектурного решения скопируйте [adr.md](adr.md) в следующий файл `docs/architecture/decisions/NNNN-short-name.md`. Пример заполненного комплекта — [SPEC-001](../specs/001-access-and-self-report/spec.md).

Файлы:

- [current-task.md](current-task.md) — рабочая задача, редакция, аппрув, критерии, самопроверка и долг; копируется в корень, не в `specs/`.
- [spec.md](spec.md) — цель, границы, поведение и критерии.
- [plan.md](plan.md) — контракты, данные, безопасность и проверка.
- [tasks.md](tasks.md) — порядок реализации и результаты.
- [acceptance.md](acceptance.md) — воспроизводимые сценарии и фактические свидетельства.
- [traceability.json](traceability.json) — машинные связи и статусы.
- [adr.md](adr.md) — контекст, решение и последствия.
