## Запрос и цель

Разработчик сообщил, что браузер запрашивает общий логин/пароль, и первоначально попросил production для реальных пациентов. После уточнения изменил объём: «хорошо давай лучше тогда пилот просто а не прям прод». Домен и SMTP-сервис отсутствуют.

Текущая цель — **пилот только на вымышленных данных** по существующему `https://94.103.3.149`: сайт открывается без HTTP Basic Auth и общего пользователя `demo`; участники входят через существующую форму приложения. Аккаунты, подтверждение адреса, допуск врача, связь и самоотчёты сохраняются. Регистрации и восстановление пароля подтверждаются организатором через закрытый Mailpit. У пользователя не должно возникать впечатления, что письмо доставлено в его настоящий почтовый ящик.

Учебные опросники остаются доступны вошедшему пациенту с подтверждённым аккаунтом пилота. Их полный модуль перестаёт раздаваться анонимно через `/static/`; право на медицинское или неограниченное публичное применение не заявляется. Ответы и расчёты остаются в памяти вкладки.

Основание — уточнённое поручение разработчика, FR-010/FR-015, CON-001/CON-002/CON-008/CON-010 и NFR-003/NFR-008/NFR-013 из [реестра](../../docs/product/requirements.json). Техническое изменение существующих [SPEC-001](../../specs/001-access-and-self-report/spec.md) и [SPEC-002](../../specs/002-questionnaires/spec.md), продолжение [WORK-0013](WORK-0013.md). Новые продуктовые функции и роли не вводятся.

## Границы и риски

Входит:

- Удалить общую HTTP Basic Auth из текущего интернет-режима, сохранить доверенный HTTPS, ограничения proxy и защиту API серверной сессией.
- Перенести доставку существующего модуля опросников за проверку действующей роли пациента, подтверждения адреса и активности аккаунта на сервере. Исключить исходное, хешированное и сжатое представления модуля из публичной статики. Исходный `questionnaires.js`, вопросы, версии и расчёты сохранить побайтово.
- Загружать модуль перед открытием опросников с понятными состояниями загрузки/сбоя/повтора, без обхода роли и без возврата ответов прежнего пользователя при выходе/смене аккаунта.
- Уточнить надпись пилота и сообщения регистрации/сброса под реально используемую операторскую почту.
- Обеспечить место для этой поставки на прежнем диске, первый/повторный запуск, сохранность данных и возможность отката к текущей WORK-0013.

Не входят реальные пациенты и медицинские данные, production-допуск, покупка домена/услуг, внешний SMTP, новые клинические правила, шкалы, чаты или постоянное хранение ответов опросников. Первоначальный запрос production заменён решением о пилоте; отдельный production-бэклог по предположениям агента не создаётся. К медицинской и правовой проверке из Q-004/Q-008 в [открытых вопросах](../../docs/product/open-questions.md) текущий пилот не приравнивается.

Пилот остаётся организованным тестированием: подтверждение почты и одобрение врача выполняет оператор по существующим процедурам. Наличие формы регистрации не предоставляет доступ к опросникам или чужим данным. Не отключать обязательное подтверждение адреса и не назначать врача по пользовательскому вводу.

До аппрува разрешены чтение, проверки существующего состояния и этот файл. Код, спецификации, текущий сайт и конфигурация пока не меняются.

Основные риски: публикация старого статического URL опросников после снятия Basic Auth, ранний вызов ещё не загруженного модуля, гонка при выходе/смене пользователя, потеря прежних данных и нехватка диска. Обновлять приложение с закрытым модулем **до** снятия общей защиты; при отказе не объявлять публикацию успешной и сохранять текущую версию/копию для восстановления.

Уточнение реализации шага 6: места достаточно для импорта, но недостаточно для одновременного хранения транспортного архива на SSD и импорта с резервом 256 MiB. Использован существующий временный tmpfs `/dev/shm`, без нового сервиса, расширения диска и дополнительных удалений. Сначала архив принимается на SSD и проверяется по размеру/SHA-256, затем проверенная копия временно переносится в закрытый каталог tmpfs (0700, файл 0600), исходный транспорт убирается и Docker импортирует RAM-копию. Копия удаляется при завершении/ошибке контекстным менеджером. Дисковая оценка учитывает максимум последовательных фаз, а не их сумму; полный размер образа и прежние 256 MiB сохраняются в проверке.

Этот путь разрешается только после проверки версии Docker 29.9.2/containerd, реального наличия базовых raw blob через ctr content ls, совпадения префикса RootFS и измеренных по Docker save размеров/хешей слоёв. Полный размер образа должен покрывать две копии нового tar-слоя и 16 MiB метаданных; для tmpfs и MemAvailable требуется тройной размер архива, чтобы оставить запас после копирования. Предпосылки повторно проверяются под блокировкой и перед импортом, размеры сверяются с полученным архивом. Неполные метаданные, иной store/версия, отсутствующие blob или недостаток памяти возвращают прежнюю полную дисковую оценку либо останавливают работу без изменения сайта. Это не снижение дискового резерва и не автоматическая очистка.

Первичные источники, сверенные 2026-10-25 для этого уточнения: [Moby Docker 29.9.2 image import](https://github.com/moby/moby/blob/docker-v29.9.2/daemon/containerd/image_exporter.go), [containerd importer этой версии](https://github.com/moby/moby/blob/docker-v29.9.2/vendor/github.com/containerd/containerd/v2/core/images/archive/importer.go). Архив/сырой blob и unpacked snapshot учитываются отдельно; наличие слоя не выводится из одного тега. До поставки создана новая отдельная контрольная вымышленная запись и приватные хеши секретов/TLS для проверки сохранности.
