## Запрос и цель

Поручение разработчика в чате: «давай так, мне нужно, чтобы все было заполнено, вместе с секретами» после инструкции локального запуска сайта с бэкендом. Подготовить приватный `.env`, с которым можно выполнить локальный запуск существующего приложения без ручного ввода настроек и секретов. Это служебная настройка уже реализованной Docker-поставки WORK-0008; продуктовые требования, спецификации и поведение приложения не меняются.

Предыдущая завершённая задача — `tasks/completed/WORK-0009.md`.

## Границы и риски

Входит создание `.env` в корне проекта с правами `0600`, независимая генерация `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`, заполнение применимых локальных настроек и проверка Compose без вывода секретов. Явное поручение разработчика разрешает работу с этой приватной конфигурацией; посторонние файлы с секретами не читаются.

Секреты сохраняются только в `.env`. `.env.example` остаётся общим шаблоном. Значения секретов, развёрнутая конфигурация Compose и содержимое приватного файла не выводятся в чат, отчёт и команды. Действующие `.gitignore` и `.dockerignore` исключают `.env`; при проверке записывается только результат проверки исключений.

Создание аккаунтов, seed-данных, замена секретов действующей БД, изменение Docker-образов, сборка и запуск контейнеров в объём не входят. Не требуется внешний SMTP или подключение сторонних сервисов: используется существующий Mailpit. Его авторизация не настроена и не требует фиктивного SMTP-пароля.

До аппрува выполнены только чтение, проверка существующего состояния и подготовка этой задачи. На 2026-10-23 `.env` отсутствует и не является символической ссылкой; Docker CLI установлен, доступ текущего процесса к Docker socket запрещён. Это ограничение окружения не мешает проверке `docker compose config --quiet`, которая не обращается к daemon. Если до выполнения появится существующий `.env`, не перезаписывать его и не заменять значения автоматически; сначала проверить состояние в пределах поручения и сохранить действующие секреты.

Принцип минимализма: использовать стандартный модуль Python `secrets` и существующие Compose-настройки. Не добавлять зависимости, генераторы конфигурации, новые сервисы и проверки продуктового поведения.

## План выполнения

1. После аппрува повторно проверить отсутствие `.env` и символической ссылки. Для нового файла с эксклюзивным созданием и правами `0600` сгенерировать `secrets.token_urlsafe(64)` для Django и независимо `secrets.token_urlsafe(32)` для PostgreSQL. Если файл уже появился, не выполнять эксклюзивное создание или автоматическую перезапись; отдельно оценить его полноту без раскрытия значений.
2. Заполнить локальную конфигурацию: `APP_DEV_MODE=1`, `APP_BASE_URL=http://localhost:8000`, `DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1`, `APP_PORT=8000`, `MAIL_PORT=8025`, `POSTGRES_DB=compass`, `POSTGRES_USER=compass`, `SMTP_HOST=mailpit`, `SMTP_PORT=1025`, `SMTP_TLS=0`, `MAIL_FROM=no-reply@example.test` и два сгенерированных секрета. Не задавать SMTP_USER и SMTP_PASSWORD: Mailpit не требует учётных данных. POSTGRES_HOST уже установлен Compose и не требует дублирования.
3. Проверить файл локальным Python-процессом: наличие всех перечисленных переменных, непустые независимые секреты необходимой длины, отсутствие шаблонных значений, права `0600` и применимые исключения Git/Docker. Выводить только результаты проверок без значений или отпечатков секретов. Выполнить `docker compose --env-file .env --profile dev config --quiet` с отключённым выводом развёрнутой конфигурации. Влияние переменных оболочки на подстановку проверить без раскрытия значений и при необходимости очистить только конфликтующие переменные в дочернем проверочном процессе.
4. Внести фактический результат в `PROJECT_STATUS.md`, проверить `TECH_DEBT.md` и записать отсутствие нового долга либо обнаруженные ID. Новые продуктовые возможности не заявлять. Самопроверку разместить непосредственно в этой задаче, без отдельного отчёта.
5. Выполнить `python3 scripts/check_sdd.py` и `python3 -m unittest discover -s tests -v`. Для каждого CHECK записать фактические команды, результаты и свидетельства без приватного содержимого. Завершённую задачу перенести целиком в `tasks/completed/WORK-0010.md`, вернуть `CURRENT_TASK.md` в `idle` со ссылкой на архив и повторить структурную проверку.
