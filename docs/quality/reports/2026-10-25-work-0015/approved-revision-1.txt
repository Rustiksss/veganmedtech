## Запрос и цель

Разработчик попросил открывать Mailpit с любого устройства без SSH-туннеля. Подготовить операторский доступ по **https://94.103.3.149:8443/** с отдельным логином и паролем. Это общий тестовый почтовый ящик пилота: обладатель реквизитов видит письма всех его участников, включая подтверждение адреса и сброс пароля. Реквизиты предназначены организатору; обычный аккаунт пациента/врача не предоставляет доступ к ящику.

Основание — явное служебное поручение разработчика, продолжение [WORK-0014](tasks/completed/WORK-0014.md), FR-010, CON-010, NFR-003/NFR-008/NFR-013 из [реестра](docs/product/requirements.json). Уточнение технической поставки [SPEC-001](specs/001-access-and-self-report/spec.md), без нового продуктового требования PDF.

## Границы и риски

Входит существующий Caddy, отдельный HTTPS-порт 8443, один операторский пароль, обновление повторяемого --internet и проверка браузером. Отдельный origin позволяет сохранить нынешние пути Mailpit, его работающий контейнер и письма: изменение webroot/пересоздание Mailpit не требуется. Прямой 18025 остаётся на loopback; наружу предоставляется только защищённый proxy. Основной сайт на 443 продолжает использовать обычную форму приложения.

Не входят домен, внешний SMTP, реальные данные, production-допуск, индивидуальные ящики участников, новая роль приложения, новая служба, обновление Mailpit/Caddy и переработка регистрации. Не менять frontend/backend приложения, состав зависимостей, ответы/источники опросников, схему БД и Compose Mailpit. Не удалять образы/версии/тома/копии и не уменьшать резерв 256 MiB. Дополнительных расходов нет.

Риски: обход пароля через API/статику/WebSocket, раскрытие ссылок подтверждения, утечка Cookie/Authorization в upstream или логах, попадание Basic Auth на основной сайт, конфликт порта/внешняя фильтрация, нехватка диска, потеря существующих писем при ненужном recreate. Отдельный порт — часть URL; сеть устройства должна разрешать исходящее HTTPS-соединение к 8443. Физический телефон не считать проверенным по одному viewport.

До аппрува меняется только CURRENT_TASK; разрешены чтение и проверки существующего состояния. Поручение открыть Mailpit задаёт цель, но не подменяет ревью конкретной редакции.

## План выполнения

1. После явного аппрува редакции 1 записать согласующего, дату и свидетельство. До кода уточнить AC-001-42 / TEST-001-42, TASK-001-36–38 и трассировку SPEC-001; дополнить существующий ADR-0003 решением об операторском доступе через отдельный origin. Новые требования и ADR не вводить.
2. В deploy/Caddyfile добавить отдельный HTTPS-сайт 94.103.3.149:8443 с теми же проверенными ACME issuer/profile/storage и Basic Auth на **все** маршруты. После проверки пароля proxy направляет в существующий 127.0.0.1:18025. Сохранить исходный Host с портом для проверки Origin Mailpit; WebSocket проходит через тот же защищённый proxy. Не разрешать wildcard CORS. Удалять Cookie приложения и Authorization из запроса upstream после аутентификации, перезаписывать недоверенные proxy-заголовки. Для ящика задать no-store. Проверить, что порт 443 не получил пароль оператора и не маршрутизирует письма.
3. В scripts/deploy.sh создавать один раз независимые реквизиты operator и случайный пароль в приватном /opt/veganmedtech/config/mailpit-access.json (0600, запрет symlink, без перезаписи исправного файла). bcrypt получить установленным Caddy через stdin, не через argv. В /etc/veganmedtech/proxy.env передавать только нужный хеш вместе с существующим TLS-окружением. Повторно использовать проверенные реквизиты; при испорченном/неполном файле завершать с ошибкой без публикации ящика. Не читать/использовать прежние demo-access.json или локальные .env*. Секреты, тела писем и токены не выводить в логи/отчёты/чат. Организатор получает реквизиты один раз по своему SSH, затем использует их в браузере на нужном устройстве.
4. Расширить preflight проверкой 8443: свободен либо занят именно управляемым Caddy с ожидаемым PID/маркером. Чужую службу не останавливать, её порт не переназначать. Сохранить прежние Caddyfile/proxy.env перед изменением; проверить конфигурацию и готовность HTTPS/пароля. Интернет-проверка должна подтверждать главную 443 без Basic и ящик 8443: без пароля/с неверным паролем 401, с правильным — 200 и рабочий API. Прямые служебные порты остаются закрытыми. При внешнем блокировании 8443 явно зафиксировать препятствие, не заявлять успешный доступ; правила чужого firewall и SSH не менять.
5. Добавить адресные проверки в tests/test_deploy.py для отсутствующих/повреждённых реквизитов, стабильности пароля и прав, чужого порта, отказа proxy/readiness и отсутствия ложного успеха. Проверить настоящим Caddy защиту UI, assets, API и WebSocket, сохранение Host/Origin и удаление Cookie/Authorization. В tests/browser/run.py добавить отдельную проверку Mailpit с реквизитами только для origin :8443: оператор видит своё новое синтетическое письмо, открывает его, получает новую почту без reload через WebSocket и использует ссылку подтверждения/сброса. Браузер 1440/390 px, строгая проверка сертификатов; содержимое писем/ссылок в артефакты не сохранять.
6. Выполнить первый и повторный bash scripts/deploy.sh --internet с проверенным повторным использованием неизменного образа приложения. До/после сравнить ID существующего Mailpit-контейнера и набор прежних message ID без вывода содержимого; новые проверочные письма не должны вытеснять старые. Сохранить секреты, TLS storage, БД, прежние письма/реквизиты и резерв >=256 MiB. Не пересоздавать Mailpit ради этого доступа. При недостатке места остановиться до изменения сайта; дополнительные удаления/расходы потребуют отдельного решения. Проверить существующий интернет-прогон обеих ролей и чужого пациента после изменения proxy; повторять серверные/расчётные наборы отдельно не требуется при неизменном приложении.
7. Обновить README с адресом, назначением общего операторского ящика, способом получения реквизитов и конкретным откатом Caddy к предыдущей конфигурации; сохранить инструкцию SSH-туннеля как альтернативу. Самостоятельно проверить каждый CHECK, сохранить обезличенные свидетельства. Обновить PROJECT_STATUS и TECH_DEBT по фактам, задачи/трассировку. Выполнить SDD/unit-тесты, архивировать только завершённую задачу и вернуть CURRENT_TASK в idle; после переноса повторить обе команды.

Технические первичные источники, проверенные 2026-10-25: [Mailpit HTTP proxy](https://mailpit.axllent.org/docs/configuration/proxy/), [Mailpit v1.30.0 config](https://github.com/axllent/mailpit/blob/v1.30.0/config/config.go), [Caddy basic_auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth), [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy). Текущие версии сохраняются. Mailpit требует сохранения Host для совпадения с Origin; отдельный HTTPS-origin без изменения webroot выбран, чтобы не терять временное почтовое хранилище при recreate.
