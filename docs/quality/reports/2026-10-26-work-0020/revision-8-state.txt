## Изменение редакции 8 — широкий подбор по скорости и цене ответа

Последние решения разработчика: **«нет, нужны быстрые ответы, попыток можно больше делать»**; на конкретный вопрос о замене прежнего потолка 6/12 ₽ за миллион ответил **«Да, до 0,10 ₽ за короткий ответ»**. Редакция 7 с одним Qwen/остатком шесть попыток не одобрена и не выполнялась. Редакция 5 с 90 с также не одобрена/не выполнялась. [Одобренная редакция 6 и её результаты](docs/quality/reports/2026-10-26-work-0020/revision-6-results.txt) сохранены: 24 попытки всего, Mistral Small/NeMo не прошли 18 с, модель/файлы/данные/конфигурация/теги работающего сервера не менялись.

Цель этой редакции — самостоятельно найти **одну быструю недорогую текстовую модель/маршрут в существующем Polza** по измерениям и закончить тот же опубликованный демоалертинг. Не привязывать согласование к двум заранее выбранным Mistral или одному Qwen. Следующий кандидат/маршрут внутри перечисленных ограничений не требует новой редакции; окончательный ID/параметры фиксируются по успешным проверкам. После выбора один фиксированный runtime, без автоматического выбора модели/перебора/платного повтора при пользовательском запросе.

### Цена и бюджет

Прежние тарифные 6/12 заменяются для подбора критерием **до 0,10 ₽ за один короткий контрольный ответ с нашей системной инструкцией**. По свежему первичному `/api/v1/models` и деталям модели проверять конкретный маршрут и его RUB-цены. Верхнюю цену контрольного случая рассчитывать до генерации: `(сумма UTF-8 байт содержимого сообщений + 1024 на framing) × prompt_price / 1e6 + 512 × completion_price / 1e6`, плюс явно заданная плата за запрос, если есть. Это консервативно ограничивает токены без новой зависимости; не полагаться на дешёвый кеш. Отбирать только проходящие 0,10 ₽, фиксировать unit-потолки provider.max_price и проверять фактический usage/cost после запроса. `max_price.request` не выдавать за общий предел стоимости токенов: это фильтр request fee. Если цены изменились/контракт не допускает ограничения — кандидата не вызывать.

Допустим конечный общий бюджет **до 60 контрольных попыток, включая прежние 24**, то есть максимум 36 новых по <=0,10 ₽, максимум 3,60 ₽ новых контрольных расходов. Не требуется расходовать бюджет целиком: остановиться после работающего подтверждённого выбора. Каждая диагностическая попытка записывается, неуспешная не обнуляет счёт. Запросы только явные последовательные контрольные случаи; автоматических runtime-повторов/неограниченного цикла нет.

0,10 ₽ относится к коротким контрольным запросам. Для произвольного диалога с более длинной историей стоимость зависит от входных токенов; не обещать фиксированную цену любого сообщения. Runtime получает фиксированные unit-потолки выбранного проверенного маршрута, прежние ограничения частоты/выхода/срока/истории; дополнительные клинические сведения не передаются.

### Выбор и скорость

Сначала прочитать свежие модели/маршруты, выбрать до 12 осмысленных кандидатов/маршрутов для диалога и JSON (например, актуальные Flash/Lite/Nano, небольшие Qwen/другие instruction-модели). Не возвращаться к уже провалившимся парам модель/маршрут без конкретного исправления. Batch/flex/приоритет на экономию с отложенной обработкой не использовать для интерактивного чата. Учитывать заявленную поддержку параметров и ограничения исходного разработчика по первичным документам. Для OpenAI выполнено чтение официальной документации; отдельный новый OpenAI-ключ/SDK не нужен, используется существующий Polza.

Выбираются Chat Completions на прежнем проверенном HTTPS-origin `polza.ai`; другой внешний сервис/аккаунт/ключ не подключается. Скрининг с нашей инструкцией и собственным вымышленным текстом: не более 18 с; при ошибке/неверном JSON/позднем полном ответе кандидата остановить, перейти к следующему. Нельзя принимать один ранний токен за готовый ответ. Для прошедшего — обязательные четыре случая (собственное упоминание/нейтральное/отрицание/прошлое), **каждый полный ответ <=10 с, медиана <=5 с**, русский reply/строгая схема/дословные цитаты/правильный статус и время. Затем 2 настоящих случая через HTTPS. Если надёжно прошёл первый подходящий — можно выбрать его, не испытывая весь каталог; при нескольких прошедших предпочесть меньшую полную задержку, затем цену. Это проверка данного прогона, не производственная SLA/клиническая валидация.

Параметры: 512 выходных токенов, TIMEOUT=18 с, Gunicorn=30 с, pending=25 с и stop_grace_period=35 с сохраняются. Рассуждения выключать только документированным способом; если модель требует reasoning, допустим подтверждённый минимальный режим в том же общем лимите 512 и бюджете, без извлечения/показа/сохранения скрытого reasoning. Неподдерживаемые поля не отправлять. JSON mode использовать только при заявленной поддержке маршрута; иначе системная JSON-инструкция остаётся единственной просьбой о формате, а строгий серверный разбор обязателен. Не снимать Markdown/think/лишние поля для фиктивного прохождения. Provider pin/сортировка по полной скорости/throughput в том же тарифном потолке допустимы как необходимые исправления для скорости; fallback/платный retry в runtime выключены.

После выбора runtime-allowlist: только выбранный ID и прежний DeepSeek для совместимости/отката, а не каталог кандидатов. Удалить не понадобившиеся ветки Mistral/Qwen и тесты предположений; не сохранять их как будущую функцию. Если понадобится компактнее системная инструкция для цены/скорости, разрешено сокращать только повторы и формулировки, сохраняя полный набор медицинских запретов, правил конфиденциальности/доставки/ролей и фактических возможностей; демополитика/категории/клинические правила не меняются. Проверить те же защитные/семантические случаи. Для меньшего контекста оставлять только до 10 собственных целых пар, удаляя старейшие до консервативного размера prompt; текущий текст/системную инструкцию не обрезать и историю БД не менять. Без нового токенизатора/SDK/зависимости/сервиса/очереди/streaming.
