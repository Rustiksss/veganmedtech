# Технические метрики «Клинического компаса»

Состояние на 2026-10-27, [WORK-0021](../../tasks/completed/WORK-0021.md). Документ описывает существующую реализацию; наличие сборщика само по себе не означает выполнение всех NFR.

Пилот: Caddy → Django/Gunicorn, PostgreSQL, браузерный интерфейс на JavaScript; один сервер, два процесса Gunicorn. Чат использует Cohere R7B через Polza. Алертинг работает только с демонстрационной политикой, клиническое распознавание выключено. Данные вымышленные. Сбор метрик не вызывает модель и не меняет приложение.

## Запуск сборщика

Нужны локальный Python 3, сохранённый SSH-алиас `veganmedtech-server` и существующие Docker/Django на сервере. Ничего устанавливать не требуется. Из корня репозитория:

```sh
python3 scripts/collect_metrics.py --hours 24 --output /tmp/compass-metrics.json
```

`--hours` — от 1 до 168; другой сохранённый алиас можно передать через `--ssh`. Отчёт создаётся локально. Команды на сервере только читают состояние; SQL выполняется в read-only транзакции с таймаутом 5 с на запрос. Сборщик не читает `.env`, ключи, тексты сообщений, ответы опросников, почту и содержимое дампов. Обычные логи фильтруются на сервере: наружу выходят только агрегаты разрешённого формата, без путей запросов и исходных строк.

В JSON есть `collected_at` (UTC, время окончания сбора), `window_hours`, статусы шести источников `sources` и 13 элементов `metrics`. При недоступном источнике сохраняются `unavailable` и пустые показатели, код завершения — 1. При ошибке SSH отчёт не выдумывается. Это отдельный снимок, непрерывного мониторинга/автоматического расписания нет.

Для длительностей `samples` — размер выборки, `mean_ms` — среднее, `p50_ms` — медиана, `p95_ms` — элемент отсортированного ряда с номером `ceil(0,95 × n)`, `max_ms` — максимум. В Gunicorn `%D` выражен в микросекундах, поэтому делим на 1000 ([исходный код Gunicorn](https://github.com/benoitc/gunicorn/blob/master/gunicorn/glogging.py)). Доля 5xx = количество наблюдаемых 5xx / число распознанных запросов. Нулевая длительность не подставляется вместо отсутствующего измерения.

HTTP-окно ограничено текущим контейнером и последними 5000 строками, включает health-проверки. Полнота при перезапуске/ротации не гарантирована, разбивки по URL нет. Выборки длительностей БД — до 5000 последних значений каждого вида; счётчики статусов — по всему окну. Состояния/длительности чата относятся к ходам, созданным за окно; демособытия — к событиям, созданным за окно с текущей версией политики. Числа строк/размер БД относятся ко всем данным; ресурсы/health — к моменту чтения. Источники читаются последовательно, это не единый атомарный снимок. Docker показывает использованную память и отображаемый лимит, который не следует считать гарантированным выделенным ресурсом. HTTPS измеряется с самого сервера. Сборщик тоже кратковременно использует CPU/БД.

## Ручной замер сценария

Откройте приложение на вымышленных данных, вставьте содержимое [measure_scenario.js](../../scripts/measure_scenario.js) в DevTools Console и начните замер:

```js
CompassScenario.start('self_report');
```

Выполните сценарий, затем завершите его:

```js
JSON.stringify(CompassScenario.stop(), null, 2);
```

Скопируйте JSON в локальный файл. Типы сценариев: `login`, `self_report`, `view_history`, `assistant_message`, `doctor_notification`. `CompassScenario.cancel()` отменяет замер и убирает обработчики. Помощник ничего не отправляет, не читает значения полей/тексты/идентификаторы/cookies. Результат без лишних полей можно приложить при следующем сборе:

```sh
python3 scripts/collect_metrics.py --output /tmp/compass-metrics.json --scenario-file /tmp/scenario.json
```

В [реальном снимке 2026-10-27](reports/2026-10-27-work-0021/metrics.json) все шесть источников доступны. Распознано 337 HTTP-ответов: p50 32,262 мс, p95 82,759 мс, 5xx — 0 из 337; это наблюдения, не SLA. В окне есть два завершённых и пять неуспешных ходов, включая прежние проверки. Эргономика не измерялась реальным пользователем: её значения отсутствуют. [Самопроверка](reports/2026-10-27-work-0021/verification.md) отдельно описывает проверку помощника искусственными событиями.
