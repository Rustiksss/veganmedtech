# ADR-0002: Django, PostgreSQL и локальная поставка в Docker

Дата: 2026-10-20. Статус: принято по аппруву WORK-0008, редакции 1.

## Контекст

Разработчик одобрил первый серверный срез: аккаунты, две роли, связь, самоотчёт и Docker. Существующий интерфейс — обычный HTML/CSS/JavaScript. Нужны хранение и серверная изоляция пациентов без внешних сервисов.

## Решение

Python 3.13, Django 5.2 LTS, DRF, PostgreSQL 18/Psycopg 3. Аккаунты обслуживает django-allauth headless browser API, пароли — Argon2id, сессии — таблицы Django. Счётчики ограничений allauth общие в PostgreSQL database cache; активные счётчики не вытесняются. Допуск врача и связь проверяются при каждом запросе, меняются только оператором через management commands с аудитом.

Gunicorn запускает WSGI-приложение; WhiteNoise отдаёт только собранные публичные ресурсы. HTML-шаблон, статика и API находятся на одном origin. Существующий frontend переносится в frontend/templates и frontend/static, без нового UI-фреймворка. backend содержит config и обычные Django-приложения accounts/care/reports/audit. Данные опросников отделены от UI и не меняются.

Собственный образ собирается по uv.lock, без подключения к БД и реальных секретов; runtime работает непривилегированным пользователем. Compose запускает app/db и опциональный dev Mailpit. БД имеет постоянный том; PostgreSQL 18 монтируется в /var/lib/postgresql по официальному образу. Публикуются только loopback-порты app и dev-почты. Внешняя почта, TLS и размещение не входят в поставку; защищённые настройки включены по умолчанию, HTTP требует явного локального dev-режима.

## Рассмотренные варианты

FastAPI потребовал бы отдельно выбирать и связывать аккаунты, ORM и миграции. NestJS также пригоден, но не даёт преимуществ текущему HTML-интерфейсу и срезу. Django предоставляет нужные инструменты вместе. Отдельный identity provider для одного локального сайта добавляет лишний сервис. Новый React/Vue-проект не нужен для подключения существующего UI к API.

## Последствия и проверка

Регистрация врача создаёт ожидающую заявку. Подтверждение почты не даёт врачебных прав; оператор отдельно одобряет заявку и задаёт ведущего врача. Новый пациент начинает с пустой историей. Клинические функции, чаты и сохранение опросников не реализуются этим решением.

Точные версии закреплены в pyproject.toml/uv.lock и образах; основания API проверяются по документации выбранной версии. Проверка — CHECK-01–CHECK-14 WORK-0008: PostgreSQL-тесты доступа/конкуренции, браузер, Docker, пересоздание контейнеров и восстановление копии. Заявление о медицинской или правовой готовности не делается.
