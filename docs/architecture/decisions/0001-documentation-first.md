# ADR-0001: начать с документационного каркаса SDD

Дата: 2026-10-18. Статус: принято в рамках текущего поручения.

## Контекст

В каталоге находится только исходный PDF. Пользователь просит сначала создать основу для SDD с ИИ-агентами. В PDF заданы задачи и ограничения медицинского продукта, но не указаны стек, инфраструктура, проверенные клинические правила и источники.

## Решение

Создать локальный документационный каркас без фреймворка приложения, облачных сервисов и клинических рекомендаций. Реестр требований хранить в JSON, спецификации и решения — в Markdown. Структурные проверки выполнять стандартной библиотекой Python; для повторного извлечения PDF использовать `pdftotext`.

Стек приложения **ещё не выбран**. Перед первым срезом создать ADR-0002 с вариантами, ограничениями команды и способом локального запуска. По возможности начать с модульного приложения с серверной авторизацией и транзакционным хранилищем; это рекомендация для анализа, а не принятое технологическое решение.

## Рассмотренные альтернативы

- Немедленно создать приложение на произвольно выбранном стеке: ускоряет видимый старт, но закрепляет неоговорённые зависимости до определения контуров доступа и работы с данными.
- Подключить специализированную SDD-платформу: возможна позже; для исходной задачи добавляет необязательную зависимость.
- Оставить только `AGENTS.md`: не даёт проверяемых требований, трассировки и конкретного первого среза.

## Последствия

Каркас можно использовать разными ИИ-агентами и будущими стеками. Сейчас нет работающего интерфейса и команд сборки сайта. Первый срез потребует выбрать стек, аутентификацию, модель хранения и добавить подходящие проверки кода.

## Проверка

`python3 scripts/check_sdd.py` проверяет структуру и связи. `python3 scripts/extract_source.py --check` сверяет текст с исходным PDF. Эти команды не подтверждают безопасность или клиническую пригодность будущего приложения.
