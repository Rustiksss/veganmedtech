# ADR-0003: закрытая демонстрация через публичный HTTPS

Дата: 2026-10-25. Статус: принято по аппруву WORK-0013, редакции 1.

## Контекст и решение

Разработчик поручил доступ с других устройств через интернет к 94.103.3.149. Приложение с аккаунтами и четырьмя локальными опросниками уже поставлено по WORK-0012; ограничения контента сохраняются. На диске 5 GB около 552 MiB свободного места.

Один готовый бинарный файл Caddy 2.11.7 на хосте, отдельный пользователь/systemd и постоянное закрытое TLS-хранилище. Это обходится без дополнительного контейнерного образа и отдельного клиента продления. Явный ACME issuer Let's Encrypt/profile shortlived нужен для доверенного IP-сертификата. HTTP 80 только для ACME/HTTPS redirect, сайт 443; proxy направляет в 127.0.0.1:18008. Mailpit и PostgreSQL наружу не открываются.

Basic Auth защищает весь сайт, включая тексты статических опросников: аккаунт приложения сам по себе их не закрывает. Независимый случайный пароль создаётся один раз на сервере; Caddy получает bcrypt-хеш. Реквизиты доступны оператору в файле 0600, не публикуются в отчётах. Серверная сессия и права приложения проверяются дополнительно. Это закрытая техническая демонстрация, без медицинского/правового допуска.

Caddy заменяет заголовки HTTPS/IP своими значениями и удаляет Authorization перед upstream. Приложение явно включает доверие proxy только в интернет-режиме, сохраняет Secure-cookie и CSRF одного HTTPS origin. App loopback недоступен интернет-клиенту напрямую. Прямой локальный режим не доверяет forwarded headers.

Поставка сохраняет серверные секреты/том/копии и TLS storage, не выполняет автоматической очистки. Неизменный образ повторно используется только после проверки переносимого content ID/метки/архитектуры. Ошибки ACME/readiness не заменяются HTTP или самоподписанным сертификатом.

## Уточнение WORK-0014, редакция 1, 2026-10-25

Разработчик одобрил пилот на вымышленных данных с обычной формой входа вместо общего Basic Auth. Публичны главная и общий код интерфейса; полный модуль опросников исключён из collectstatic и выдаётся отдельным GET с PatientOnly/no-store. Источник и расчёты неизменны, ответы по-прежнему локальные. Внешняя почта и домен не подключаются; интерфейс объясняет операторское подтверждение через Mailpit.

Сначала поставляется защищённая доставка модуля, затем снимается общая защита Caddy. Старые приватные реквизиты сохраняются для отката, но не используются новой поставкой. Точная адресная очистка старого неиспользуемого образа допускается только в рамках аппрува WORK-0014 после проверки локальной копии; общий prune отсутствует, резерв 256 MiB сохраняется.

Проверенные первичные источники: [collectstatic --ignore](https://docs.djangoproject.com/en/5.2/ref/contrib/staticfiles/), [Docker save и восстановимая копия](https://docs.docker.com/reference/cli/docker/image/save/). Применимость проверки слоёв и фактические размеры сверяются на локальном Docker classic и серверном containerd до использования в оценке места.

## Уточнение WORK-0015, редакция 1, 2026-10-25

По аппруву разработчика добавляется операторский HTTPS-origin https://94.103.3.149:8443 для существующего Mailpit. Один listener того же Caddy защищает UI/API/assets/WebSocket отдельным Basic Auth. Основной origin :443 использует сессии приложения. Mailpit остаётся на loopback без смены webroot и recreate: его временные письма сохраняются. Host с портом сохраняется для Origin, Cookie приложения и Authorization до Mailpit не доходят. Реквизиты приватны и стабильны при повторе; ящик общий для организатора и содержит ссылки доступа всех участников. Это пилот, не доставка на настоящую почту. Источники/проверки — в [WORK-0015](../../../tasks/completed/WORK-0015.md).

WORK-0015, редакция 2: согласована разовая адресная очистка воспроизводимых APT-кэшей под штатными блокировками; пределы и перечень — в текущей рабочей задаче. Повторяемый deploy не очищает кэши/образы и не снижает резерв 256 MiB.
