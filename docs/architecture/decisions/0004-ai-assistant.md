# ADR-0004: Серверный ИИ-ассистент через Polza AI

Дата: 2026-10-25. Статус: принято в WORK-0016, редакции 1, по явному аппруву разработчика.

## Контекст и решение

FR-017/B-23 требуют недорогой чат и основу уведомлений. Используем существующий Django/PostgreSQL, стандартный HTTPS-клиент Python и серверный POLZA_API_KEY. Модель deepseek/deepseek-v4-flash, без reasoning/tools; лимиты токенов, частоты и тарифов обязательны. Короткоживущий daemon-thread ограничивает ожидание ОС/DNS общим сроком 18 секунд; истёкший бюджет проверяется перед HTTP-запросом, позднее разрешение DNS не запускает генерацию. Блокировка строки пациента сериализует новые попытки между worker, сетевой вызов вне транзакции; результат сохраняется отдельно. Собственный текст чата хранится на сервере, в Polza передаётся ограниченный диалог без профилей/карты/опросников.

Проверено 2026-10-25: [Chat Completions](https://polza.ai/docs/api-reference/chat/completions), [маршрутизация и max_price в RUB за 1M](https://polza.ai/docs/gaidy/provider-selection), [карточка модели](https://polza.ai/models/deepseek/deepseek-v4-flash), [политика Polza](https://polza.ai/docs/osobennosti/privacy). Фактический GET models подтвердил модель, optional reasoning с none и текущую цену 2,57741417/5,15482834 RUB за миллион; различия с карточкой допустимы внутри потолка 4/8. Контент провайдеру передаётся; условия реальных медицинских данных не подтверждены.

## Альтернативы и последствия

SDK/агентный фреймворк, отдельная очередь и векторная база не нужны текущему текстовому диалогу. Браузерный вызов раскрывает ключ. Текстовая заглушка не выполняет запрос разработчика. Внешний провайдер — новая зависимость с возможными отказами и списаниями; сетевой timeout не доказывает отсутствие внешнего списания, автоматических повторов нет. Собственная идемпотентность защищает строки/уведомления, а не обещает абсолютную однократность биллинга Polza.

## Клиническая граница и проверка

Пустой шаблон критериев, детектор выключен. Только внутренние синтетические события проверяют сохранение и показ текущему ведущему врачу. Без push/внешней почты/обещания экстренной реакции. Для реального распознавания требуется отдельное решение Q-005 и медицинское согласование. Проверки — [SPEC-005](../../../specs/005-ai-assistant/acceptance.md). Пересмотр при изменении этих границ; существенное изменение WORK требует нового аппрува.

## Поставка WORK-0017, 2026-10-26

По аппруву редакции 1 ключ и фиксированная модель добавляются к прежней приватной серверной конфигурации; существующие секреты не генерируются заново. Старые конфигурации совместимы, неизвестные/неполные поля отклоняются. Единственное разовое освобождение — три согласованных неиспользуемых тега WORK-0013 после восстановимой локальной копии. Повторяемый deploy не выполняет очистку. Проверки публикации — AC-005-11 / TEST-005-11, WORK-0017.

## WORK-0020: отдельный демонстрационный режим, 2026-10-26

Редакция 1 одобрена разработчиком. `ASSISTANT_ALERTING_MODE=off|demo`, по умолчанию off, не включает клинический детектор. В demo тот же единственный ограниченный вызов Polza возвращает JSON с ответом и описанием возможных сигналов текущего сообщения. Сервер проверяет схему, известные категории, временной контекст и дословное основание, сам добавляет статические подписи/источники. Дополнительного вызова/SDK/очереди нет. Результат, OneToOne-событие и аудит записываются одной транзакцией; невалидный/прерванный ответ — явный сбой, а не отсутствие сигнала. Политика версии хранится отдельно от пустого клинического шаблона. Невозможность анализа при отказе Polza — явная граница демонстрации; клиническая надёжность не заявляется. Старые ходы не пересчитываются. Права и кабинетный канал прежние. Поставка только локальная; данные и текущий HTTPS-сайт не обновляются.

## Публикация WORK-0020, редакция 3

Одобрена 2026-10-26. Деморежим включается на существующем HTTPS явно, клинического детектора нет. Добавочные серверные DEFAULT при необходимости сохраняют возможность INSERT прежнего приложения после миграции. Необязательное поле режима строго валидируется скриптом поставки. Для текущего диска разрешена только адресная замена старого предыдущего образа проверенным локальным архивом; current WORK-0019 остаётся на сервере для немедленного отката, после успеха станет previous. Порядок/ограничения и резерв не менее 256 MiB заданы в рабочей задаче. Внешний прогон/повтор/сохранность/серверный restore требуются до завершения; само одобрение не является свидетельством публикации.

## Уточнение тарифов WORK-0020, редакция 4

Одобрено 2026-10-26: «WORK-0020, редакция 4 — одобряю». Из-за актуальных цен первичного API 5.41990030/10.83980061 RUB за миллион разрешены потолки 6/12 вместо исторических 4/8. Модель, 512 токенов, 18 секунд, частота, контекст, один запрос и отсутствие автоповторов прежние. Бюджет контрольных вызовов — до 18 с учётом выполненных неуспешных попыток. До публикации новый клиент загружается вместе с инструкцией только в память процесса на сервере, исходный клиент сверяется с известным SHA-256; ключ не копируется. Проверка нового контракта относится к CHECK-02/07/12 WORK-0020; исторические результаты 4/8 не объявляются проверкой новых потолков.

Фактический результат WORK-0020, редакции 4: код/миграции опубликованы, runtime demo/clinical=false и сохранность подтверждены после двух deploy. Живой путь до события не подтверждён из-за таймаутов генерации, включая минимальные контроли; ошибка явно показана, события при ней нет. Это внешний блокер приёмки, а не разрешение сменить модель/расширить лимиты или объявить клиническое распознавание. [Протокол](../../quality/reports/2026-10-26-work-0020.md); задача не архивирована.

## WORK-0020, редакция 8 — широкий выбор по фактической скорости

Одобрена 2026-10-26. По свежим метаданным Polza сравниваются до 12 текстовых моделей/маршрутов, без batch/flex. Максимум 60 контрольных попыток включая прежние 24; до 0,10 ₽ на короткий контрольный ответ по консервативной предгенерационной оценке и фактическому cost, максимум 3,60 ₽ новых контрольных расходов. Полный ответ четырёх синтетических случаев <=10 с, медиана <=5 с, строгая схема/цитата/время/русский reply; два опубликованных случая также <=10 с. Максимум 512 выходных токенов/18 с/6 новых попыток в минуту/100 в сутки/до 10 своих пар, без runtime-перебора или повторов. Параметры и reasoning выбираются только из документированной поддержки конкретного маршрута. После успеха runtime фиксирует один ID/маршрут/тарифные потолки, legacy DeepSeek остаётся для отката. Самостоятельный переход между кандидатами внутри этих границ не требует новой редакции. Клинический детектор выключен. Поставка/сохранность/ровно два старых тега WORK-0019 и серверный restore заданы CURRENT_TASK.md. Результат пока не подтверждён.
