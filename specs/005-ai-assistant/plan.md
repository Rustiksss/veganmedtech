# План SPEC-005

Статус: актуальный. WORK-0016, редакция 1 одобрена разработчиком 2026-10-25. Решение: [ADR-0004](../../docs/architecture/decisions/0004-ai-assistant.md).

## Контракты и данные

GET/POST `/api/me/assistant/messages`, GET `/api/me/assistant/messages/{id}` — только PatientOnly; POST принимает text 1–2000 и Idempotency-Key, прочие поля отклоняются. GET список: limit 1–100 (30), подписанный cursor; последние сверху, UI отображает хронологически. POST синхронно выполняет одну ограниченную генерацию: 201 новый ход, 200 сохранённый, 202 ещё выполняется; конфликт тела 409. Состояния pending/completed/failed/interrupted, безопасный код ошибки. Повтор завершённого/ошибочного ключа сам не вызывает провайдера. Для сознательной новой попытки после ошибки новый ключ; после потери ответа сначала проверка старого ключа. Просроченный pending через 25 секунд считается interrupted; запись сохраняется, без автоматической отправки.

AssistantTurn: пациент, ключ, text, reply, status/error_code, model, prompt_version, usage, created_at/finished_at. AssistantAttempt: пациент/время — отдельная запись каждой новой попытки для общих лимитов между процессами. Одна active pending на пациента через блокировку User; вызов вне транзакции. Ограничение 6 за последние 60 секунд, 100 за последние 24 часа. Лимит хранения контекста — 10 последних завершённых пар и текущий text.

GET `/api/doctor/assistant-notifications`, GET/POST `/api/doctor/assistant-notifications/{id}` — допущенный текущий ведущий врач, список с пагинацией, POST с пустым телом отмечает seen. Список/деталь/изменение проверяют связь и роль на сервере; patient row lock синхронизирует изменение связи. AssistantNotification: OneToOne к ходу, synthetic=True, policy_version, created_at/seen_at/seen_by. Текст только из связанного хода; общая история врачу недоступна. Внутренний create_synthetic_notification не имеет публичного маршрута, запись и аудит атомарны. Новый ведущий врач видит сохранённое событие, статус просмотревшего прежнего врача не раскрывает его профиль. Отказ БД не подтверждает доставку, повтор после восстановления не дублирует.

## Polza и интерфейс

Серверный ключ окружением, фиксированный HTTPS URL, запрет redirect, проверка TLS, абсолютный бюджет сетевого ожидания 18 секунд и максимум 64 KiB ответа. Без reasoning, streaming и tools; max_tokens=512, provider.sort=price и max_price.prompt/completion=6/12 (редакция 4 WORK-0020, ранее 4/8). Проверка фактического model без подмены; ошибки не содержат ответа провайдера/запроса/ключа. Системная инструкция описывает только реальные возможности и отсутствие детектора. Исходящий контекст — только собственный диалог.

Существующий раздел ассистента: сообщения, черновик, загрузка/повтор/история; карточки настроения/опросников сохраняются. Кабинетные уведомления с демомаркировкой обновляются раз в 15 секунд при видимом кабинете, просмотр отдельным действием. При ошибке/отзыве доступа личное содержимое убирается; поздние ответы ограничены поколением сессии. Полный текст выводится как текст, доступность проверяется клавиатурой и в Firefox на 1440/768/390 px.

## WORK-0020 — контракт demo

Режим сервера `off|demo`, off по умолчанию; `automatic_detection_enabled=false` сохраняет прежнее значение клинического детектора, отдельно возвращаются `alerting_mode` и `demo_detection_enabled`. Режим фиксируется на каждом новом ходе. В demo системная инструкция запрашивает JSON `{reply, analysis: {status, signals: [{category, quote, time}]}}`; status matched/no_match/uncertain, time current/past/unclear. Не более 8 разных категорий, цитата 1–240 символов и дословно из текущего сообщения; известные категории из демополитики, неуверенность имеет отдельную подпись. no_match требует пустого списка, matched/uncertain — непустого. Неизвестные/лишние поля, дубли категорий и повреждённая структура отклоняются. Подписи и источники добавляет сервер. Один сетевой вызов, прежние 512 токенов/18 секунд/лимиты/цены; история до 10 собственных пар. Старые ходы остаются not_evaluated, off использует прежнюю беседу.

AssistantTurn дополняется режимом, analysis_status, policy_version и analysis (список оснований с серверными подписями/источником). Итог хода/анализ/OneToOne-уведомление/аудит атомарны; синтетическое ограничение уведомлений сохраняется. При сетевом сбое/невалидном JSON анализ failed, при прерывании demo-pending — failed; not_evaluated не выдаётся за отрицательный результат. При отказе финальной транзакции сохраняется исходный pending; повтор ключа не вызывает модель, проверяется история/прерывание и доступен сознательный новый повтор. Утрата HTTP-ответа не дублирует сохранённое событие.

Пациентские list/detail/post возвращают серверные режим/анализ и состояние `notification_status`: none/available/no_doctor. Доступность пересчитывается из текущей активной связи с действующим допущенным и подтверждённым врачом; событие сохраняется и без врача. Врачебные API прежние, добавлены сохранённые основания/тип события. Текст только связанного хода, без общей истории. Просмотр явно отдельный, лечение/направление не меняются. UI показывает режим до отправки и исход анализа после; старые события узнаваемы как техническая проверка доставки. Реальный Polza проверяется до 4 короткими вымышленными запросами. Проверки — CHECK-01–08 WORK-0020; PostgreSQL/изолированный Compose, браузер/миграция/recreate/restore, без SSH-публикации.
