# План SPEC-002

Решение WORK-0007, редакция 1, 2026-10-20: обычный script `questionnaires.js` с конкретными данными четырёх методик и чистым расчётом. Индекс страницы подключает его до своего скрипта, поэтому file URL работает без fetch, сервера и сборки. Это локальное расширение, не выбор стека приложения. Зависимости не добавляются.

Контракт `CompassQuestionnaires`: `list`, `get(id)`, `score(id, answers)`. Неизвестный ID и неполный/некорректный массив отклоняются без выдачи баллов. В списке — инструкции, источники, версия и вопросы, ключи не зависят от UI. Результат — total/min/max (если есть), groups, summary, note; таблицы Столина возвращают накопленную частоту и исходную категорию. Типы ответов различаются строго: boolean, enum string или integer. Ноль/false не являются пропуском.

В `index.html`: маршруты /patient/questionnaires и /patient/questionnaires/{id}; черновики по ID {answers, step, started, result, showResult, causes, error}. Отдельные ответы не включаются в URL, storage, логи или сеть. Любое изменение ответа сбрасывает устаревший результат. Ввод причин ограничен 500 символами на поле, экранируется при показе; поле может быть пустым. Навигация не меняет фиксированную связь врача. Серверных запросов нет.

Формы: явный старт после инструкции, fieldset/legend и radio без начального выбора, подписанные значения 0–10 и крайние якоря, прогресс по числу заполненных пунктов. Три причины — отдельный заключительный шаг. Отправка проверяет полный набор и переводит к первому отсутствующему/неверному ответу. Ошибка локального расчёта сохраняет ввод и предлагает повтор. Возврат к ответам, каталог и начало заново доступны с клавиатуры; сброс требует отдельного явного нажатия на подтверждение внутри страницы.

Сначала сверить источники и создать спецификацию, затем данные, независимые ожидаемые значения и `tests/questionnaires.html`, затем UI. Расчётные примеры проверяются в Firefox; браузерный прогон использует существующий WebDriver BiDi с временным профилем и Python websocket среды. Никаких новых зависимостей проекта. Проверки — AC-002-01–AC-002-10 и TEST-002-01–TEST-002-10. Результаты записываются после фактического запуска.

Источник ключа ИЖУ 2022 имеет противоречие: максимум 40 в описании, но 39 в таблице. Реализуется буквальная таблица, без самовольного исправления первого пункта. Для Столина таблица не достраивает отсутствующие пункты ключа. Оба различия раскрываются до начала и в результате; это предел применимости демонстрации. Открытые вопросы не считаются клиническим допуском.

## Журнал решений WORK-0014, редакция 1, 2026-10-25

Basic Auth и требование DEMO_PASSWORD_HASH отменяются только после проверки приватной доставки модуля. Постоянные секреты/TLS/том сохраняются; резерв 256 MiB не снижается.
