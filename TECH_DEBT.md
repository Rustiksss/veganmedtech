## Правила ведения

- Сразу при обнаружении или возникновении конкретного долга добавьте запись `TD-NNN`. Укажите текущую рабочую задачу; после завершения добавьте ссылку на неё в архиве.
- Долг — известный технический компромисс, дефект или отложенная необходимая работа с описанными последствиями. Отсутствующие плановые функции и неразрешённые продуктовые вопросы не объявляются долгом автоматически.
- Исключённые из объёма пожелания агента не переносятся в долг или отложенный бэклог. Реализуется только необходимое сейчас для согласованной задачи.
- Статусы: `open`, `in_progress`, `resolved`. Приоритеты: `high`, `medium`, `low`, с объяснением влияния. Укажите ответственную роль; не выдумывайте назначенного человека.
- Не скрывайте долг общей формулировкой «улучшить позже». Запишите последствия, способ устранения и наблюдаемый критерий закрытия.
- Для устранения оформляется и согласуется рабочая задача. Закрытую запись сохраняйте с датой, результатом и свидетельством. Номера не переиспользуются.
- Перед завершением любой задачи проверьте реестр и запишите в `completion.technical_debt_result` найденные/изменённые ID либо «Новый технический долг не обнаружен». Само отсутствие строк в реестре не заменяет эту проверку.

### TD-006 — полный HTTP-ответ ошибочно становится unavailable после закрытия сокета

Статус: `resolved`. Приоритет: `high` — корректный быстрый ответ может быть потерян, чат показывает недоступность и не сохраняет демоанализ. Обнаружен 2026-10-27, ответственная роль — технический исполнитель WORK-0020.

Происхождение: [WORK-0020](tasks/open/WORK-0020.md), редакция 9, `backend/assistant/client.py`, цикл чтения `_exchange`. После `read1`, дочитавшего Content-Length, `HTTPResponse` закрывает свой file object. При Connection: close закрывается сокет. Следующая итерация вызывает `sock.settimeout` до проверки EOF и получает EBADF; обработчик превращает его в unavailable, хотя полное тело уже получено. Прямой контроль Llama/Groq дал HTTP 200/OSError за 1,583 с; отдельное локальное воспроизведение с настоящим HTTPResponse подтвердило один вызов timeout на закрытом сокете и ложный unavailable без сетевых запросов. [До исправления](docs/quality/reports/2026-10-26-work-0020/closed-response-before.json), [воспроизводитель](docs/quality/reports/2026-10-26-work-0020/repro-closed-response.py).

Устранение в рамках согласованного исправления клиента: завершать цикл при закрытом HTTPResponse, не обращаться к уже закрытому сокету; сохранить общий deadline/предел размера/строгий JSON и отсутствие повторов. Критерий закрытия: HTTPResponse с Content-Length и Connection: close успешно возвращает весь ответ; нет settimeout на закрытом сокете; фрагментированный/неполный/просроченный/слишком большой ответ не обходит прежние проверки, PostgreSQL-регрессия проходит. Живые скорость и сквозная доставка проверяются отдельно, исправление этого дефекта само по себе не делает WORK-0020 завершённой.

Локальная самопроверка 2026-10-27: после фикса воспроизводитель возвращает completed/0 обращений к закрытому сокету; 75 PostgreSQL-тестов прошли, включая целое/фрагментированное тело и incomplete при оборванном Content-Length. [После исправления](docs/quality/reports/2026-10-26-work-0020/closed-response-after.json), [полный прогон](docs/quality/reports/2026-10-26-work-0020/server-read-fix-rev9.txt). Статус остаётся in_progress: опубликованный клиент всё ещё прежний; rollout заблокирован условием успешного выбора модели, не выполненным в редакции 9. [Отчёт](docs/quality/reports/2026-10-26-work-0020/revision-9-results.md). Других новых программных дефектов не зарегистрировано; изменение свободного места отражено как непройденное условие поставки в текущей задаче, неподтверждённая причина не объявляется новым дефектом.

Закрыт 2026-10-27 публикацией WORK-0020: новый клиент с исправленным закрытием HTTPResponse и Cohere установлен в версии20261027T135844Z-9d467081; источник проверен по хешу, реальный backend-вызов завершён с201/completed. Прежние75 PostgreSQL-тестов воспроизводят полный/фрагментированный и оборванный Content-Length. Закрытие TD-006 не подтверждает качество демоанализа. [Публикация и свидетельства](docs/quality/reports/2026-10-26-work-0020/deployment-rev13.md).

## Формат записи

Новая запись содержит:

1. ID и короткое название.
2. Статус, приоритет и обоснование влияния.
3. Дату обнаружения и ответственную роль.
4. Описание и причину; последствия, если не устранить.
5. Происхождение: рабочая задача и затронутые файлы/функции.
6. Предлагаемое устранение и зависимости.
7. Проверяемый критерий закрытия.
8. Для `resolved`: дату, задачу устранения и свидетельство фактической проверки.

Статус: `resolved`. Приоритет: `high` — первый деплой заполнил небольшой диск сервера, PostgreSQL не смог создать pg_wal, поставка не готова. Обнаружен 2026-10-24; ответственная роль — технический исполнитель WORK-0012.
